# Сценарий правильного парсинга дневника в Kira Diary

**Цель:** полностью автоматизировать и стандартизировать процесс парсинга дневника Ивана в структурированные данные на сайт.

---

## Фаза 1: Распознавание дневника

Триггеры:
- "Дневник за N число"
- "Дневник N число"
- "Запись за сегодня / за N число"
- Любое сообщение с день, сон, настроение, события, деньги, работа, планы

**→ Вход:** текстовый дневник Ивана (голос или текст)

---

## Фаза 2: Парсинг в структуру

**Извлечь ВСЕ поля:**

### 1. Дата
- Если указано число (N) → текущий месяц/год
- Если "сегодня" → сегодняшняя дата
- Формат: `YYYY-MM-DD`

### 2. Сон
```
- sleep_time: время засыпания (если помнит)
- wake_time: время пробуждения (если помнит)
- duration_hours: 4, 6, 8+ часов / "нормально" / "плохо" (текст или число)
- quality: "хороший", "с пробуждениями", "беспокойный", "норм"
```

### 3. Настроение и состояние
```
- mood_morning: "хорошее", "нейтральное", "плохое", конкретная фраза
- mood_day: основное настроение дня (было событие? как изменилось?)
- mood_evening: (если есть данные)
- mood_now: сейчас (сейчас в баре, позитив и т.п.)
- energy: "активный", "медленный", "вялый", "быстрый", оценка 1–10
- stress: "низкий", "средний", "высокий", уровень
- anxiety: "есть", "нет", "беспокойство про...", конкретная причина
- body: "хорошо", "болит...", "усталость", физическое состояние
```

### 4. События
```
- Перечень дневных действий: "гулял", "встретил X", "пошел гулять", "работал"
- Только значимые события, не минуты
```

### 5. Здоровье
```
- symptoms: ["маниакальная фаза", "болит голова"], конкретные
- doctor: [] визиты, консультации
- medicine: [] таблетки, лечение
- analysis: ["изучал восстановление после маниакальной фазы"]
- notes: ["нужно спортом", "нужен белок"]
```

### 6. Работа
```
- done: [] завершённые задачи / проекты
- main_useful_action: "главное полезное действие дня" (одно)
- productivity: "сделал", "в процессе", "ничего", оценка
```

### 7. Деньги
```
- income: [] заработки
- expenses: ["медовуха в баре"]
- debts: []
- loans: []
- balance_notes: "в баре, потратился на медовуху"
```

### 8. Нужды / Планы
```
- needs: ["хорошо покушать с белком", "спортом заниматься", "проект сделать"]
- tomorrow: ["надежда не будет спада", "спорт и белок"]
```

## Фаза 3: Расчёт Kira Score

**Использовать KIRA_SCORE_PROTOCOL.md:**

```
Kira Score (0–10) = (
  sleep_component (0–25) +
  actions_component (0–30) +
  habits_component (0–20) +
  state_component (0–15) +
  honesty_component (0–10)
) / 10
```

### Примеры

**15-е число:**
- Сон: 6–8 часов → 20
- Действия: Hermes Agent install (значимое) → 10
- Привычки: не указаны → 5
- Состояние: нейтральное → 10
- Честность: записал, но мало → 5
- **Итого:** 50 / 10 = **5.0**

**16-е число:**
- Сон: нормально → 20
- Действия: 2 прогулки + встреча + изучение восстановления → 20
- Привычки: беспокойство про еду, но не сделал → 8
- Состояние: маниакальная фаза (не норма) → 5
- Честность: осознал и записал маниакальную фазу → +10
- **Итого:** (20+20+8+5+10) = 63 / 10 = **6.3**

## Фаза 4: Заполнение site_blocks

**site_blocks** — это то, что выводится на фронтенд (Kira Diary сайт):

```json
{
  "mood": "8 / 10 (маниакальная фаза — внимание!)",
  "energy": "8 / 10 (быстрый, активный)",
  "needed": "Белок, спорт, контроль состояния",
  "health_detail": "Маниакальная фаза — нужна коррекция; изучал восстановление",
  "stress": "Низкий, но беспокойство про завтра",
  "what_helps": "Спорт, режим, белок, осознанность",
  "month_status": "День 16: активный, требует внимания"
}
```

**Правила для site_blocks:**
- `mood`, `energy`: числовая оценка (X / 10) + краткое описание
- `needed`: компактный список из 2–3 пунктов (без длинных предложений)
- `health_detail`: детализированный анализ здоровья (может быть длиннее)
- `stress`: уровень + причина (если есть)
- `what_helps`: конкретные действия
- `month_status`: одно предложение про день

## Фаза 5: Сохранение в БД

**Файл:** `/root/workspace/kira-diary/data/entries.json`

**Формат:** JSON объект, ключ = дата `YYYY-MM-DD`

```json
{
  "2026-05-16": {
    "date": "2026-05-16",
    "logged": true,
    "raw_transcript": "...",
    "kira_score": 6.3,
    "sleep": { ... },
    "state": { ... },
    "events": [ ... ],
    "health": { ... },
    "work": { ... },
    "money": { ... },
    "needs": [ ... ],
    "tomorrow": [ ... ],
    "site_blocks": { ... }
  }
}
```

**Правила:**
- Если запись за эту дату уже есть → UPDATE (не создавай дубликат)
- Если новая → ADD
- После каждого сохранения → Git commit + push

---

## Фаза 6: GitHub Sync

```bash
cd /root/workspace/kira-diary

# 1. Добавить в staging
git add data/entries.json

# 2. Коммит с понятным сообщением
git commit -m "diary: add/update YYYY-MM-DD entry"

# 3. Пуш на master
git push origin master

# 4. Синхронизировать с live сайтом
cp data/entries.json /var/www/html/data/entries.json
```

## Питфоллы (не допускать!)

### ❌ ОШИБКА: Психоанализ
**Неправильно:** "Это маниакальная фаза указывает на дисбаланс серотонина..."
**Правильно:** "Маниакальная фаза — осознал, нужна коррекция через спорт и белок"

### ❌ ОШИБКА: Разные шкалы Score
**Неправильно:** День A = 5.6, День B = 68
**Правильно:** День A = 5.6 / 10, День B = 6.3 / 10

### ❌ ОШИБКА: Дублирование записей
**Неправильно:** Две записи за 2026-05-16
**Правильно:** UPDATE существующую запись

### ❌ ОШИБКА: Забытый Git sync
**Неправильно:** Данные только в `/var/www/html`, репо устаревает
**Правильно:** Коммит + push на GitHub сразу после сохранения

### ❌ ОШИБКА: Пустые поля
**Неправильно:** `events: []`, `health: {}` (если есть данные в тексте)
**Правильно:** Извлечь ВСЕ события и здоровье из текста дневника

## Чеклист для каждой записи

- [ ] Дата определена корректно
- [ ] Все поля заполнены (или отмечены null если нет данных)
- [ ] Kira Score рассчитан по протоколу (0–10 шкала)
- [ ] site_blocks заполнены компактными текстами
- [ ] Запись сохранена в `/root/workspace/kira-diary/data/entries.json`
- [ ] Git: add → commit → push выполнены
- [ ] Live файл обновлен: `cp ... /var/www/html/data/entries.json`
- [ ] Ответ отправлен (без психоанализа)
